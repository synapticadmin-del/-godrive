## What I actually did

1. **Four payout endpoints on `adminRoutes`** — queue, detail, approve, reject. **Every balance
   move goes through E06's exported `settlePayoutRequest` / `rejectPayoutRequest`;** `admin.ts`
   contains no `wallet_balance` or `wallet_transactions` statement and `wallet.ts` is unmodified.
   E06's failure codes map to HTTP in one table (404/409/409/400) instead of being re-decided per
   call site, and approve/reject share one body so they cannot drift.
2. **`SafetyPage`** — the SOS queue, polling every 10s so "within seconds of it firing" is true.
   **It adds no API:** E13 already shipped the whole admin surface under `/safety/sos*`, so the
   console calls it rather than growing a second copy in `admin.ts`. Detail view renders the
   append-only trail and says so.
3. **`PayoutsPage`** — the payout queue, showing the captain's current balance next to each
   request so an operator sees an uncoverable payout before clicking rather than after.
4. **`ReasonPrompt`** — one mandatory-reason modal behind all six destructive actions, mirroring
   the server's `min(3)` rather than inventing a second bar. Payout decisions log with E12's
   `critical: true` flag, which had no caller until now. Generalised from `RejectionReasonModal`,
   which is document-specific and was left untouched.

   all four CI jobs' commands passed: both typechecks, the admin build (three new chunks emitted),
