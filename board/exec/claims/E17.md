## What I actually did

1. **targetSdk 34 -> 35 on both apps.** compileSdk was already 35, so no AGP move was needed and
   nothing outside owns had to be touched. Both gradle files stay byte-identical apart from
   namespace/applicationId — the captain's copy was generated from the rider's by substituting
   those two strings, so the diffs are line-for-line identical.
2. **Release signing fails closed, two mechanisms.** With any signing input missing, the `release`
   signingConfig is never created (so signingConfigs.debug is not merely unselected — there is
   nothing to fall back to and the build type carries `signingConfig = null`), and a
   `gradle.taskGraph.whenReady` guard throws GradleException naming each missing input. Checked on
   the task graph, not at configuration time, so `flutter run` / `--debug` / `analyze` still work
   with no keystore, and a release build stops before any task executes.
3. **Signing inputs also resolve from the environment** (ANDROID_KEYSTORE_PATH / _PASSWORD /
   ANDROID_KEY_ALIAS / ANDROID_KEY_PASSWORD), key.properties winning. The one addition not literally
   named by the brief; it is what lets CI sign without writing a secrets file into the workspace.
4. **Rider Info.plist:** removed the UIBackgroundModes `location` entry and
   NSLocationAlwaysAndWhenInUseUsageDescription. Kept `remote-notification` — main.dart:13-16/:21
   registers a FirebaseMessaging.onBackgroundMessage handler, so stripping the whole key (a literal
   reading of the brief) would have been a silent behaviour regression. Deviation disclosed on the PR.
5. **Proposed workflow + runbook in docs/plan/assets/** (PROTOCOL-EXEC §8 — no workflows permission).
   The workflow leads with a negative test: a keystore-less `flutter build appbundle --release` must
   exit non-zero, log "release signing is not configured", and leave no artefact. Before this PR that
   job could not have failed.
