## What I actually did

1. **`cron/dispatch.ts` — the expiry sweeper (gate item 7, root R6).** `searching`/`offered` past a
   10-minute TTL move to `cancelled` with `cancel_reason = 'expired_no_captain'`, which is terminal,
   already understood by every client, and clears the `ACTIVE_TRIP` guard. A new `expired` status
   would need `packages/shared/src/index.ts` plus both Flutter apps — three files in nobody's `owns`.
   The sweep tears down the `OfferScheduler` rollout, revokes share tokens, closes any pending
   `scheduled_trip_dispatch` row, and tells the rider by FCM **and** trip-room broadcast. Every
   transition is a conditional UPDATE, so a captain accepting in the same second wins the race.
2. **`cron/dispatch.ts` — scheduled rides actually dispatch (gate item 9).** The job used to flip a
   status column and notify *admins*; no captain was ever offered the trip. It now calls
   `dispatchTrip`. Paired with the `!scheduledFor` gate in `trips.ts`, which is also what makes the
   job's `t.status = 'searching'` predicate reachable — the dead `WHERE` and the early dispatch were
   one bug seen from two ends. `pingDeadMan("scheduled-dispatch", …)` on both the success and failure
   paths (E12's seam). Timestamps compare through `datetime()` on both sides (root R7): a raw string
   compare would have cancelled trips booked in the future.
3. **`trips.ts` — the call sites four other tasks were waiting on.** `POST /:id/accept` records the
   agreed price via E08's `resolveTripSettlement` (gate item 6 — `offered_price` was read nowhere);
   `POST /:id/complete` stops hand-rolling a fourth price chain and lets `settleTripCompletion`
   resolve; booking passes `allowFallback: false`, retries once, then returns 503 `ROUTE_UNAVAILABLE`
   and writes `route_source` at the INSERT (gate item 11, with E15); `osrmUrl()` adopts
   `resolveOsrmBaseUrl` so an unset `OSRM_URL` no longer reaches the public demo server;
   `revokeShareToken` at every terminal transition (gate item 10, with E13); the dead `logAudit`
   import removed (F-22-05).
4. **`GET /trips/active`** (gate item 7, server half), registered ahead of `/:id`. Each role's
   predicate is copied byte-for-byte from the guard that would otherwise lock it out — rider from
   `ACTIVE_TRIP`, captain from `BUSY` — because a recovery endpoint that disagrees with its guard is
   the bricked account again with an endpoint confirming nothing is wrong.
5. **`lib/dispatch.ts` + `lib/cleanup.ts`.** `writeTripEvent` gives the cron a trip-event writer
   without creating `lib/tripEvents.ts`, which E03 correctly refused to create because it is in
   nobody's `owns`. `purgeExpiredShareTokens` wired into the daily expired-data pass with its count on
   the existing audit row — the only reason `lib/cleanup.ts` is in this task's `owns` at all.
   `OfferScheduler.ts` was reviewed and left unchanged: its alarm already self-terminates.
