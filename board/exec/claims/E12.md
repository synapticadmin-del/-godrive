## What I actually did

1. **`lib/health.ts` — a probe that can fail (F-22-02).** Was a static literal answering 200 while
   D1, KV or R2 were broken, and it is the only gate in the deploy smoke test. Now probes all three
   in parallel — `select 1`, and a `get`/`head` of a nonexistent key where the miss is the pass — with
   a 2s per-binding ceiling, returning 503 with per-binding `{ok, error, ms}`. `checkHealth(env)` kept
   its name, argument and return shape, so the frozen call site in `index.ts` was not reopened; E02
   sized that signature for exactly this and both reserved properties are now used.
2. **`lib/audit.ts` — failures countable, never fatal (F-22-07).** Was swallowed into `console.error`.
   Now increments `audit_write_failed` and returns `{ok:false, id, error}`. Never-throw was kept
   deliberately. `critical: true` (E08's flag for the money path) logs at `error` with its own counter
   dimension. Return type widened from `Promise<void>`; existing call sites still compile.
3. **`lib/log.ts` — new, the single sink (F-22-08, §5.4).** Single-line JSON, `counter()`,
   `loggerFor()`, secret redaction, and **`pingDeadMan(job, env, outcome)`** exported for E07 and E09
   to call from their own cron files. It emits `cron.heartbeat` unconditionally, so an alert works off
   the log stream before any secret exists; it pings `<url>/fail` on a failed run; and it cannot throw.
   Logpush left off per T22's constraint.
4. **`middleware/requestId.ts` — new (F-22-04).** Accepts a well-formed inbound `X-Request-Id`
   (validated before trusted — an unchecked header lets a caller forge log lines), else mints one;
   echoes it, re-stamps after `next()`, emits one `http.request` line with the *resolved* `routePath`
   to keep cardinality flat, and counts `http_5xx`.
