> **Goal.** Make CI worth having.

## Why this blocks launch

The API has zero automated tests; the only two test files in the repository are in `packages/shared` (T23 F-23-04). With branch protection on (E00) CI is finally binding, which is worth nothing if nothing is tested. T23's answer to the brief's own question was blunt: a change that breaks the payment webhook can merge today with a green board, and with a red one too. Scope this to the paths that stay live under the launch shape — do not chase coverage.

## Scope

- Stand up `@cloudflare/vitest-pool-workers` so tests run inside `workerd` against real D1, KV, R2 and DO
  bindings rather than a Node approximation. **E01 already added the devDependency and the `test` script for you** — configure the
  runner in `vitest.config.ts`; do not edit `apps/api/package.json`, it is E01's.
- Tests for: cash-commission settlement including the balance floor; the completion handler's idempotency on retry; the accept race (two captains, one trip); and E04's payment-method rejections.
- Wire them into the required `ci.yml` job — **but you cannot commit it.** The App has no `workflows`
  permission and the push will fail. Put the job YAML in `docs/plan/assets/` and name the human step in your
  PR, exactly as E17 does. Committing a workflow to a path GitHub does not read is precisely how PR #46
  shipped a deploy pipeline that has never run.

## Acceptance criteria

- The suite runs in CI on every PR and can fail the build.
- Each test named above exists and fails when its fix is reverted — demonstrate that in the PR by reverting and pasting the red run.
- No test depends on network access to a third party.

## Out of scope

Anything touching a file not in `owns`. If you believe you need one, stop and say so on the PR — do not
edit it. Another chat owns it and your change will be silently lost or will lose theirs.

## Definition of done

1. One PR into `main`, small enough to read in one sitting.
2. The tests named above exist and run in CI.
3. You do **not** merge it yourself.
4. After merge, a different chat verifies the *effect* against `main` and closes the finding. You move it
   to `awaiting-verification` and stop.
