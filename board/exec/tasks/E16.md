## Why this blocks launch

There is no privacy policy anywhere in the product or the repository (T25 F-25-01). The terms checkbox is client-side only, so no consent is recorded (F-25-02). There is no access, export, correction or erasure path of any kind (F-25-03) — and both Apple and Google **require** in-app account deletion for apps with accounts, which makes this a store rejection before the PDPL argument starts (T26 F-26-03). This task is calendar-bound more than effort-bound: start it first and expect counsel, not code, to be the long pole.

## Scope

- Write and host the policy; link it from both apps and the store listings. Content lives in `docs/legal/`.
- Record consent server-side as append-only rows — withdrawal is a new row, never an update.
- `DELETE /user/account`: soft-delete with identifier tombstoning — null the phone, name, email and avatar, set `deleted_at`, and keep financial ledger rows pointing at the tombstone. A public web deletion URL is also required by the stores.
- Export on request.
- Delete R2 document objects when their rows go (`FILES.delete` is currently called only for avatars) and reconcile the existing orphans once.
- Take the next migration number via the lock.

## Acceptance criteria

- A user can delete their account from inside both apps and from a public URL.
- **You own `app_strings.dart` for this wave** — both settings screens already read from it, and your policy
  link and deletion copy are store-review surfaces that must exist in Arabic *and* English. Add each getter in
  all three places (abstract, `AppStringsAr`, `AppStringsEn`) or `check_l10n_parity.py` fails the build. You are
  the only task allowed in this file; nobody is waiting on you for it, so take it early and keep the diff small. **E02 mounts the public route;
  you write the handler in `user.ts`.** If your PR merges first the handler is briefly unrouted — that is fine
  and expected. Do not edit `index.ts` to route it yourself; it is frozen after E02.
- Deleting a user leaves no personal identifier and no orphaned R2 object, while the ledger still balances.
- Consent is queryable per user with a timestamp and a version.
