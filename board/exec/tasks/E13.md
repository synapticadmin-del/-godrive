> **Goal.** A safety feature that lies is worse than one that is absent.

## Why this blocks launch

Trip sharing is broken twice over and unsafe once fixed. The URL handed to the sharer omits the `/safety` mount prefix, and the 'public' route sits behind `authMiddleware` — both verified on main — so the family member gets a 404 while the rider is told `ok: true`. Fixing only those two bugs would publish `pickup_address` and `dropoff_address` to an unauthenticated bearer token that lives up to 7 days and is never revoked when the trip ends (F-17-02, F-17-03). Separately `sos_alerts` is INSERT-only: no admin endpoint, no screen, and `status`/`resolved_at` are never written again (F-17-04).

## Scope

- Build the payload redaction **before** fixing the URL: status and a coarsened position, no addresses.
- Correct the URL to include the mount prefix; E02 has already moved the route to the public mount.
- Revoke share tokens at trip end and purge them on a schedule.
- Add SOS lifecycle columns and the endpoints an operator needs (list, acknowledge, resolve) — take the next migration number via the lock. The console is E14's.
- Escalate as immutable event rows rather than mutating one status field.

## Acceptance criteria

- A share link opens for someone with no account and reveals no address.
- A share link stops working when the trip ends.
- An SOS can be acknowledged and resolved, and the history is queryable.
- A test asserts every `/safety/*` path except the tracker rejects unauthenticated requests — T17's author calls this the one test they would not ship without.
