> **Goal.** Stop the product from bricking rider accounts.

## Why this blocks launch

A trip nobody accepts never leaves `searching` — no timeout, no terminal state, no sweeper — and the `ACTIVE_TRIP` guard then refuses to let that rider book again (T06 F-06-04, T09 F-09-01, T16 F-16-01, T27 F-27-06: four tracks, one hole). Requesting a ride when no captain is online is the *normal* early outcome for a platform bootstrapping supply. Scheduled rides make it routine: they dispatch at booking time rather than scheduled time, exhaust the wave rollout hours early, and land in exactly that state (F-06-01/F-16-02).

## Scope

- Add a trip-expiry sweeper to `apps/api/src/cron/dispatch.ts`: `searching`/`offered` past a TTL move to a terminal unfulfilled state and the rider is told.
- Add `GET /trips/active` so a client can recover; return the trip id in the 409 body too.
- Gate live dispatch on `!scheduledFor`, and have the cron dispatch scheduled trips at their scheduled time — or, if that is not finishable in this task, disable scheduling at the schema and say so.
- Use `lib/dispatch.ts` (E03's extraction) for both paths rather than duplicating the sequence.
- **Flip the booking call site.** E15 ships `getRoute` with `allowFallback` defaulting to current behaviour and
  cannot touch `trips.ts`. You own it: `trips.ts:382` (booking) must pass `allowFallback: false`, retry once, then
  return `503 ROUTE_UNAVAILABLE`; `trips.ts:331` (estimate) may keep falling back but must surface `source`.
  Without this, gate item 11 is half-shipped and the silent haversine price survives — that is root R3 exactly.
- **You are the call-site owner for four other tasks.** `trips.ts` is the busiest file in the repository
  (55 plan items touch it), so every task that needs a line changed there hands it to you. Do all of these:
  - **E08's accept path** — the handler at `trips.ts:829` must settle `offered_price` through E08's
    primitive. Gate item 6 does not close until this ships.
  - **E08's audit call** — `trips.ts:20` imports `logAudit` and never calls it. Remove the dead import once
    settlement owns the call, or wire the remaining call site.
  - **E13's share tokens** — call `revokeShareToken(tripId)` at trip end, and `purgeExpiredShareTokens()`
    from your sweeper. E13 exports both and is forbidden from touching `trips.ts` or any cron file.
  - **E15's `route_source`** — write the column E15's migration adds at the trip INSERT site.
- Call E12's `pingDeadMan()` from the success path of `cron/dispatch.ts`.

## Acceptance criteria

- A trip with no captain reaches a terminal state without human intervention, and the rider can book again.
- Killing the app mid-trip and reopening returns the rider to the live trip.
- A trip scheduled for +9h dispatches at +9h, or cannot be created at all.
- A forced routing failure fails the booking with 503 instead of silently pricing it off a straight line.

2. If this brief names tests, they exist and run in CI. **If it names none, say so in the PR and

   `flutter test`, so a Dart test you add today runs nowhere; wiring that up needs a workflow edit
