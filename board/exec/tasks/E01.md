> **Goal.** Stop production deploys from being an accident.

## Why this blocks launch

`apps/api/package.json:8` runs `wrangler deploy` with no `--env`, which publishes the top-level config block over production (T23 F-23-03, S1). `apps/api/deploy.sh:47` does the same and additionally applies exactly one hardcoded migration (0009) out of 19 (T22 F-22-11 / T23 F-23-17 — both tracks filed this file independently).

## Scope

- Change the `deploy:api` script to require an explicit `--env`; make the no-env form fail loudly rather than deploy.
- Fix or delete `apps/api/deploy.sh`. If kept, it must apply all pending migrations via `wrangler d1 migrations apply --remote --env prod`, never a hardcoded one.
- **Add `@cloudflare/vitest-pool-workers` to `devDependencies` while you are in `package.json`.** You will
  not use it; E19 needs it in round 5 and does not own this file. One line now costs nothing and saves a
  cross-round seam later.
- **Add a `test` script to `apps/api/package.json`:** `"test": "vitest run"`. There is none today, so `npm test -w @synaptic-go/api` fails and E19 has no way to add one — it owns `apps/api/test/` and `vitest.config.ts`, not the manifest. Failing with "no tests found" until E19 lands is fine and expected.
- **Regenerate the root `package-lock.json` in the same commit.** This is an npm-workspaces repo with a
  single lockfile at the root, and `ci.yml` runs `npm ci`, which fails outright when the lockfile has
  drifted from the manifests. You own the lockfile for exactly this reason — nobody else touches it in
  this wave. Commit the regenerated lockfile; do not hand-edit it.
- Record in `docs/DEPLOYMENT.md` the verified current state and the one command a human must run: `wrangler d1 migrations list synaptic-go --remote --env prod`.

## Acceptance criteria

- `npm run deploy:api` without an environment exits non-zero and deploys nothing.
- No script anywhere applies a single hardcoded migration.
- `@cloudflare/vitest-pool-workers` is present in `apps/api/package.json` devDependencies **and in the root
  `package-lock.json`** — prove it by showing a clean `npm ci` in the PR.
- `docs/DEPLOYMENT.md` no longer claims 17 migrations are applied with nothing pending (the repo has 19).

## Out of scope

Anything touching a file not in `owns`. If you believe you need one, stop and say so on the PR — do not
edit it. Another chat owns it and your change will be silently lost or will lose theirs.

## Definition of done

1. One PR into `main`, small enough to read in one sitting.
2. The tests named above exist and run in CI.
3. You do **not** merge it yourself.
4. After merge, a different chat verifies the *effect* against `main` and closes the finding. You move it
   to `awaiting-verification` and stop.
