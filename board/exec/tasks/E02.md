> **Goal.** Split the cron into per-job modules, correct the route mounts, then freeze this file.

## Why this blocks launch

`apps/api/src/index.ts` is the single worst merge hotspot in the repository: 36 of the 403 planned items touch it, and 7 of the 16 launch-gate items need to edit it. One handler serves both crons, ignores `event.cron`, and swallows every error into `console.error` (T22 F-22-03), so Cloudflare records 100% success while the dispatch cron does nothing. Two route mounts are also wrong: `/safety/track/:token` is the one route that must be public and it sits behind `safetyRoutes.use("*", authMiddleware)` (verified on main).

## Scope

- **Pure refactor first, in its own commit:** move each cron job out of the `scheduled` handler into `apps/api/src/cron/<job>.ts` — one file per job (`invoices.ts`, `dispatch.ts`, `cleanup.ts`, …). Behaviour identical. The handler becomes a dispatcher that switches on `event.cron` and lets errors propagate per job.
- Extract the `/health` body into `apps/api/src/lib/health.ts`; `index.ts` only delegates.
- Unmount `/intercity` and `/companies` (launch shape, §2.1 of the plan).
- Mount a public `publicSafetyRoutes` carrying only `GET /track/:token` **before** the authenticated `safetyRoutes`.
- Add the mount point for `requestId` middleware ahead of all routes. The middleware itself is E12's — mount a no-op passthrough if E12 has not merged.
- **Do not change any business logic.** Every behavioural fix belongs to a later task that owns the extracted file.

## Acceptance criteria

- Each cron job is one file under `apps/api/src/cron/`, and a failure in one job cannot silently mark the invocation successful.
- `GET /safety/track/:token` resolves without a JWT; every other `/safety/*` path still requires one.
- `/intercity/*` and `/companies/*` return 404.
- **After this merges, `apps/api/src/index.ts` is frozen.** No Wave 1 task may edit it — if you think you need to, you are missing a delegation seam and should say so on the PR instead.

## Out of scope

Anything touching a file not in `owns`. If you believe you need one, stop and say so on the PR — do not
edit it. Another chat owns it and your change will be silently lost or will lose theirs.

## Definition of done

1. One PR into `main`, small enough to read in one sitting.
2. The tests named above exist and run in CI.
3. You do **not** merge it yourself.
4. After merge, a different chat verifies the *effect* against `main` and closes the finding. You move it
   to `awaiting-verification` and stop.
