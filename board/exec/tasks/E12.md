> **Goal.** Be able to see the system before you ask it to carry money.

## Why this blocks launch

Nothing alerts — no monitor, no notification rule, no external probe exists in any file (T22 F-22-01). `/health` is a static literal touching no binding and it is the only gate in the deploy smoke test (F-22-02). There is no correlation id anywhere in the stack (F-22-04). Six other tracks each proposed their own telemetry path; §5.4 of the plan rules that this pipeline is the only sink, so build the seam they plug into.

## Scope

- `middleware/requestId.ts` mounted ahead of all routes (E02 left the mount point); id on the context and echoed in a response header.
- `lib/log.ts` emitting single-line JSON with level, route, request id.
- `lib/health.ts` (E02's delegate) actually touching D1, KV and R2.
- `lib/audit.ts`: make `logAudit` failures countable instead of swallowed (`audit.ts:33-36`), and export the seam E08 calls on the money path.
- A cron dead-man's switch — an external ping per successful job, so a silent cron is detectable.
- Alerts on 5xx rate and on payment-path failures. Do not enable Logpush until the `?token=` WebSocket parameter is gone, or JWTs get persisted to storage.

## Acceptance criteria

- A request can be traced end to end by one id.
- `/health` fails when a binding is broken.
- A cron that stops running pages someone within an hour.
- An audit-write failure increments a counter someone can see.

## Out of scope

Anything touching a file not in `owns`. If you believe you need one, stop and say so on the PR — do not
edit it. Another chat owns it and your change will be silently lost or will lose theirs.

## Definition of done

1. One PR into `main`, small enough to read in one sitting.
2. The tests named above exist and run in CI.
3. You do **not** merge it yourself.
4. After merge, a different chat verifies the *effect* against `main` and closes the finding. You move it
   to `awaiting-verification` and stop.
