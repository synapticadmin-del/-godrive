## Progress
- Reviewed the auth surface at base commit `dccc2dadf206ffaba4d35b3343d55ff279bacaf4`: all of
  `routes/auth.ts`, `middleware/auth.ts`, `middleware/rateLimit.ts`, `lib/jwt.ts`, `lib/turnstile.ts`,
  `lib/utils.ts`, `routes/devices.ts`, `wrangler.toml`, plus both Flutter apps and the admin console.
- **3 S1 blockers.** (1) Refresh rotation is non-atomic with no reuse detection, so one stolen token
  becomes a silent permanent session (`routes/auth.ts:279-295`). (2) No client anywhere calls
  `POST /auth/logout` — the endpoint exists and hard-revokes, but grepping `apps/` and `packages/`
  returns zero hits, so logging out leaves a live 30-day refresh token. (3) Turnstile is wired only to
  the suspended OTP route, leaving `/auth/login` and `/auth/register` with no bot defence, and it fails
  open when the secret is unset.
- 24 findings total (3 S1, 10 S2, 8 S3, 3 S4), each citing `path:line` and marked confirmed / likely /
  needs-check. Ordering constraint flagged: client single-flight refresh must ship before server-side
  atomic rotation, or the fix causes mass captain logouts.
- Two brief premises corrected by evidence: `SESSIONS` KV holds **no sessions** (they are in D1, which is
  strongly consistent, so the anticipated KV-staleness revocation risk does not exist — the real gap is
  that access tokens have no revocation path at all); and a suspected unauthenticated
  `POST /intercity/bookings` was **disproved** by running Hono 4.7.11 locally — `/bookings/*` does match
  the bare path. Recorded in the doc so nobody re-raises it.
- OTP descoped by operator (flow suspended); recorded as an explicit exclusion, not a clean bill of
  health. Retained reachability check found the suspended routes still mounted and still able to mint
  accounts, and surfaced that with OTP off there is now **no password-reset or recovery path at all**.
