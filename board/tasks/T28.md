## Questions you must answer

1. **Design the motion token set and write it as real Dart.** Durations, curves, and the named semantic roles that map to them (`GoMotion.enter`, `GoMotion.exit`, `GoMotion.emphasis`, `GoMotion.spring`…). Deliver the actual file content for `packages/flutter_shared/lib/motion/go_motion.dart` — constants a developer pastes in, not a table of adjectives.
2. **Specify the shared animation library.** What reusable primitives do both apps need: staggered list entrance, sheet transition, marker interpolation, pulse for live state, shimmer skeleton, success and failure confirmations, count-up for money, page transitions, hero handoff between screens. For each: the widget API (constructor signature and parameters), the behaviour, and a code sketch.
3. **Map marker interpolation — build it.** This single component changes the product's perceived quality more than any other. Specify `AnimatedVehicleMarker`: position tweening matched to the update interval, bearing rotation with shortest-arc handling, easing choice, what to do when an update is late or missing, and how to avoid rebuilding the whole map. Provide the implementation sketch, including how it interacts with `trip_ws.dart` update cadence.
4. **Choreograph the signature moments.** Pick the six moments that define this product and design each as a complete sequence — not 'it fades in', but the beat-by-beat: what moves, from where, over how long, with what curve, what the haptic is, what the sound is, and what the user is feeling. Candidates: app launch, going online (captain), a bid landing on the rider's screen, accepting a captain, the captain arriving, trip complete with the fare reveal. Each gets a storyboard table.
5. **The launch experience.** `splash.mp4` is a video file used at cold start. Assess whether a video is the right vehicle (decode cost, size, first-frame delay on a 2 GB Android device) versus Rive, Lottie, or hand-written Flutter animation. Make a recommendation with numbers, then design the launch sequence including the transition from splash into the first real screen — the handoff is usually where these fall apart.
6. **Asset pipeline.** If Rive or Lottie is recommended, specify: which moments justify an authored asset, file size budget per asset, how they are versioned in the repo, how a designer hands them over, and the fallback when an asset fails to load.
7. **Money in motion.** The fare, the earnings total, the wallet balance — should numbers count up, and when? Specify the rule and the widget. Getting this right makes the captain's earnings screen feel rewarding; getting it wrong makes it feel slow.
8. **State-change choreography.** The trip status chip changing from 'الكابتن في الطريق' to 'الكابتن وصل' is the most-watched pixel in the app. Design that transition. Same for the captain's online/offline toggle.
9. **Gesture physics.** Bottom sheets, the bid list, the map pan. Are they interruptible, do they follow the finger with the right resistance, and do they settle with velocity-aware physics rather than a fixed duration? Specify the physics parameters.
10. **Performance discipline.** For every proposed animation, state the frame cost and the mechanism that keeps it off the main thread. Define the rules: what must be wrapped in `RepaintBoundary`, where `AnimatedBuilder` scope belongs, when to use implicit vs explicit animation, and the 60 fps budget on a low-end device. An animation that janks is worse than no animation.
11. **Reduce-motion.** Every animation needs a defined still fallback. Specify the mechanism once, centrally, so no developer has to remember it. (Coordinate with T15.)
12. **Rollout plan.** Order the work so that value lands early: which three animations ship first, what they cost in developer-days, and how they are verified. Include how motion changes are reviewed — a written spec cannot be code-reviewed for feel, so define the process.

## Benchmark against

- Uber: marker interpolation and route drawing that make a 4-second GPS refresh read as continuous movement; restrained elsewhere.
- inDrive: fast and functional — motion never delays a driver's tap. Use this as the ceiling on duration for anything in the captain app.
- Material 3 motion system as the structural baseline for durations and easing, exceeded deliberately where the brand demands a signature moment.
- Revolut and Cash App: the reference for money-in-motion — counting, confirming, and celebrating a transaction without slowing it down.
