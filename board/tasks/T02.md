## Mission

Given a valid token, what can it reach? Build the complete authorization matrix for every route in the API and hunt object-level access flaws (IDOR) — the single most common critical bug class in ride-hailing backends, because trip IDs, document IDs and wallet IDs are passed around constantly.

## Questions you must answer

1. Produce the authorization matrix: for all 14 route files, every endpoint × {anonymous, rider, captain, admin, company} → allowed or denied, and where in code that is enforced.
2. For every endpoint that accepts an id in the path or body (`/trips/:id`, documents, wallet, bookings, company employees), is there an ownership check binding that object to the caller? Test the reasoning per route, do not generalise.
3. Role storage: where does the role live — in the JWT claim, in D1, or both? Can a client influence it? Is it re-read per request or trusted from the token?
4. Admin sub-roles: is every admin omnipotent? Can a support agent issue refunds, change pricing rules, read PII, delete audit rows?
5. Is `routes/admin.ts` behind an admin guard as a whole, or per-endpoint? Any endpoint that slipped outside the guard?
6. Cross-tenant leakage in `routes/companies.ts`: can company A read company B's employees, invoices, or trips?
7. Trip-participant scoping: can any authenticated captain read an arbitrary trip, its chat messages, its path points, or the rider's phone number? Check `routes/trips.ts` and `routes/safety.ts` (share tokens).
8. Share tokens (`trip_share_tokens`) grant unauthenticated access — scope, expiry, revocation on trip end, and what PII the public payload exposes.
9. Audit coverage: which state-changing admin actions write to `audit_log` and which do not. Can an admin erase their own trail?
10. Document access: R2 `FILES` bucket — are captain ID/licence images served through an authorization check or a guessable URL? PR #21 touched a document token; verify current state.
11. Mass-assignment: do PATCH endpoints whitelist fields, or spread the request body into the update?

## Benchmark against

- Uber: strict participant-scoped access with short-lived signed URLs for any media; separate internal roles with just-in-time elevation and full audit.
- Careem: regional admin scoping so an ops agent in one city cannot act on another.
- Standard: OWASP API Security Top 10 — API1 (BOLA) and API5 (BFLA) are the two to prove out here.
