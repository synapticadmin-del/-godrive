## Questions you must answer

1. Parity: run the logic of `check_l10n_parity.py` mentally against the four ARB files — which keys are missing, which are untranslated English, which are orphaned. Give counts.
2. Hardcoded strings: how many user-visible literals remain outside the ARB files in rider and captain? Search systematically and quantify by screen.
3. RTL correctness: directional icons that must mirror, `EdgeInsets` using left/right instead of start/end, `Row` ordering, text alignment in custom painters, map overlay positioning, and swipe-gesture direction. List concrete offenders with paths.
4. Numerals: Arabic-Indic (٠١٢٣) vs Western (0123) for prices, phone numbers, plate numbers and ETAs. What does the app do now, what should it do, and is it consistent? This is a real decision — make a recommendation and justify it for the Egyptian market.
5. Formatting: currency (EGP placement and spacing), distance, duration, dates, and relative times ('منذ ٥ دقائق') — is `intl` used with the right locale, or string concatenation?
6. Copy quality: is the Arabic Modern Standard, Egyptian colloquial, or a mix? Ride-hailing needs warmth and clarity — assess the tone and rewrite the twenty highest-traffic strings as an example (empty states, errors, the offer card, the SOS confirmation).
7. Error messages: the API returns structured codes (`VALIDATION_ERROR`, `RATE_LIMITED`, …). Are these mapped to human Arabic text on the client, or shown raw? Produce the mapping table as a deliverable.
8. Notification and OTP text: are push notifications, WhatsApp OTP messages, and emails localised per user preference? Where is the user's locale stored?
9. Pluralisation and gender: Arabic has dual and complex plurals, and the captain may be addressed as male or female. Does the ARB use ICU plural syntax? Is gendered copy handled?
10. Language switching: can a user change language in-app without restart, and does it persist? Does it change server-side notification language too?
11. Admin i18n: cost and approach for adding Arabic to the React console — which library, how many strings, and is it needed at launch or later? Make a recommendation.
12. Fonts: does the chosen family cover Arabic well at small sizes, and what is the font-file weight cost in the APK?

## Shared context (identical for every task)

**Synaptic Go** is an Egyptian ride-hailing platform, currently pre-production.
The product goal is a transport and delivery app with the feature depth of Uber
and the price-negotiation model of inDrive, hardened to full production quality.

**Stack.** Cloudflare Workers (Hono-style routing) + D1 (SQLite) + KV
(`SESSIONS`) + R2 (`FILES`) + four Durable Objects (`TripRoom`, `GeoCell`,
`CaptainInbox`, `OfferScheduler`) + Queues (`NOTIFICATIONS` with a DLQ) + two
cron triggers (scheduled-trip dispatch every minute, B2B invoices monthly).
Two Flutter apps (`apps/rider`, `apps/captain`) sharing `packages/flutter_shared`.
A React + Vite admin console (`apps/admin`). 19 D1 migrations. `APP_VERSION 0.4.0`.

**API surface.** `apps/api/src/routes/`: admin, auth, captain, companies,
devices, geocode, intercity, payments, promo, safety, search, trips, user,
wallet. `apps/api/src/lib/`: audit, cleanup, geocode, jwt, nearby, notifications,
paymob, pricing, routing, schemas, turnstile, types, utils.
