## Questions you must answer

1. Coverage gap: enumerate every capability in `routes/admin.ts` (and companies/intercity) and mark which have a UI. `CompaniesPage` and an intercity page are absent entirely — specify them.
2. Captain verification workflow: the highest-volume operator task. Count clicks per captain, assess the document viewer (zoom, rotate, side-by-side with entered identity fields from 0012), rejection reasons, bulk actions, and queue prioritisation. What would double an agent's throughput?
3. Trip investigation: given a complaint with a trip id, can an agent see the full timeline — offers, bids, path points, chat, payments, ledger entries — on one screen? If not, specify that screen. This is the single highest-value missing tool.
4. Live map: what does it show, how does it refresh (`usePolling`), and what is the request cost at 500 online captains? Can an operator act from the map (call, message, force-offline)?
5. Data tables: server-side pagination and filtering or client-side? What happens at 100k trips? Sorting, saved views, CSV export correctness (`csv.ts`, `escape.ts` — check formula-injection handling).
6. Destructive actions: confirmation, reason capture, audit trail, and reversibility for ban, refund, force-complete, and pricing changes. PR #40 fixed controls that reported success without saving — hunt for remaining optimistic-UI lies.
7. Pricing and config: what can be changed live from `PricingPage`/`SettingsPage` and `system_config` (0016), what validation guards it, and what stops a typo from setting the multiplier to 100.
8. Realtime vs polling: which pages poll, at what interval, and is there a smarter option (the API already has DOs).
9. Operator roles: is there any separation between support, finance, and superadmin? (Coordinate with T02 — here focus on the UI affordances that role separation would require.)
10. Support-facing gaps: no ticketing, no user-communication tool, no refund UI, no promo issuance for goodwill. Which of these are needed at launch?
11. Accessibility and density: this is a tool used for eight hours — assess information density, keyboard navigation, and dark mode consistency with the design tokens.
12. Internationalisation: the admin has no i18n at all. Do the operators need Arabic? (Coordinate with T14.)

## Shared context (identical for every task)

**Synaptic Go** is an Egyptian ride-hailing platform, currently pre-production.
The product goal is a transport and delivery app with the feature depth of Uber
and the price-negotiation model of inDrive, hardened to full production quality.

**Stack.** Cloudflare Workers (Hono-style routing) + D1 (SQLite) + KV
(`SESSIONS`) + R2 (`FILES`) + four Durable Objects (`TripRoom`, `GeoCell`,
`CaptainInbox`, `OfferScheduler`) + Queues (`NOTIFICATIONS` with a DLQ) + two
cron triggers (scheduled-trip dispatch every minute, B2B invoices monthly).
Two Flutter apps (`apps/rider`, `apps/captain`) sharing `packages/flutter_shared`.
